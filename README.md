**A personal short-drama client for Android.** Flutter UI, a thin Kotlin media plugin, and a
Dart port of the upstream protocol. v1 speaks to exactly one upstream source (红果 / hongguo) and
is **not** a clone of it — no account, no ads, no pixel-for-pixel imitation of the official app.

Three things are non-obvious enough to be worth naming up front:

- **Playback decrypts on the client.** Every sample of the upstream's video is AES-128-CTR
  encrypted, *including the NAL length prefixes*, so no stock extractor can even parse the
  container. `media3`'s `Mp4Extractor` was ruled out from source; a decryption data source was
  written instead, driven by a sample index built in Dart from `moov`. Seeking works, and
  `STATE_READY` lands in ~2.3 s rather than after a full-episode download.
- **Media resolution has three tiers** (signed app API → public web page → third-party mirror),
  each falling back to the next.
- **The protocol exists twice** — a Go reference implementation and a Dart port — cross-checked
  against shared fixtures so the two can't silently drift apart.

Status: v1.0.0 builds, is signed, and was verified item by item on a real device. The APK is not
distributed. Only Android is set up; there is no iOS or desktop target.

## Build & run

Prerequisites: Flutter **3.47.5 stable** (Dart 3.13.4), JDK 17, Android SDK (minSdk 24 /
targetSdk 36), Go **1.24.1+** (only for the protocol reference implementation's self-check).

```bash
# Dependencies. This also resolves the packages/hongguo_dart path dependency.
flutter pub get

# Device / emulator
flutter devices
flutter run
```

Release build:

```bash
flutter build apk --release      # → build/app/outputs/flutter-apk/app-release.apk, universal, ~55 MB
```

Four environment gotchas, all documented in the code, that you will hit on a different machine:

- `flutter` / `dart` are not on the **current** shell's PATH (Scoop installs only surface in a new
  terminal) — use full paths in scripts.
- **The build directory is redirected to the repo-root `build/`** (`android/build.gradle.kts`
  overrides `rootProject.layout.buildDirectory`), so Gradle outputs are not under `android/app/build/`.
- `android/settings.gradle.kts` requires `flutter.sdk` in `android/local.properties`. That file is
  gitignored and generated by the Flutter tool — **so don't run `gradlew` directly**; run
  `flutter pub get` first.
- Two workarounds for the build machine's network: Maven prefers the **Alibaba mirror**
  (`maven.google.com` was unreachable there), and Kotlin incremental compilation is disabled
  (AGP 9.1 + Kotlin 2.4 on Windows reliably fails with `Storage is already registered`).

### Signing

`android/key.properties` and `android/app/onedrama-release.p12` are **both gitignored and not in
this repo**. `android/app/build.gradle.kts` reads the former and **falls back to debug signing when
it is missing**, so anyone can run `flutter build apk --release` without the key.

> ⚠️ Back those two files up separately. Losing them means no more identically signed packages, so
> installing a new version requires uninstalling first — which wipes local favorites, history, and
> watch progress (all three are local and never synced, per `CONTEXT.md`). No root, no export.

## Self-check

All four suites pass:

```bash
cd hongguo && go test .              # ok hongguo — signature vectors, SM3, ID/episode mapping
cd packages/hongguo_dart && dart test # 32 passed, 7 skipped — contract tests
flutter test                          # 19 passed — formatting, decrypt-plan round trip, cover prefetch, transitions
flutter analyze                       # No issues found
```

The 7 skips are **default behavior**, not failures: they are live smoke tests that actually hit the
upstream API. That is the only hard evidence the signature is server-accepted — contract tests only
prove Dart and Go agree, so if both are wrong together, only this suite goes red:

```bash
cd packages/hongguo_dart && LIVE=1 dart test test/live_test.dart
```

The Go side's live endpoints need a real site and are not a unit test.

## Layout & architecture

```
onedrama/
├── lib/                       Flutter app (~7.7k lines)
│   ├── data/                  Networking (in-flight dedupe + TTL cache; streams never cached),
│   │                          three sqflite tables (drama_snapshots / favorites / watch_progress),
│   │                          settings & DeviceID, Riverpod providers
│   ├── player/                CencPlayer (MethodChannel), moov header parsing, decrypt-plan codec
│   └── ui/                    Library / rankings / detail / player / search / mine / settings / shell + widgets
├── packages/hongguo_dart/     Protocol layer (~3.8k lines) + tool/ offline-verification scripts (~1k lines)
├── hongguo/                   Go reference implementation (~2.4k lines), not shipped in the APK
├── android/                   Android shell + two Kotlin files (~494 lines)
├── docs/adr/                  Decision records: why these choices
├── docs/plan.md               Implementation plan + per-item on-device verification log (stage 0 → 4c)
├── docs/shots/                README screenshots
└── CONTEXT.md                 Domain glossary: Drama / Episode / Media / Heat / Rating
```

Data paths, each tier falling back:

```
Catalog / detail
  Signed app API  ──fail──▶  Web  (parse _ROUTER_DATA)

Stream resolution
  Signed app API  ──fail──▶  Web /player/{series}/{vid}  ──fail──▶  Third-party mirror
```

Episode addresses are placeholders of the form `hongguo-cenc://{vid}`; the real stream URL needs
one more resolution call.

## Three non-obvious things

### 1. Client-side CENC decryption instead of ExoPlayer's DRM

The upstream hands out a **raw 16-byte key**, not a license-server response, so the stock
`video_player` can't take it. Worse, every video sample is AES-128-CTR encrypted **including the
NAL length prefixes**, and `media3`'s `Mp4Extractor` unconditionally converts length-prefixed NAL to
Annex-B with no encryption branch anywhere in its source — so it reads ciphertext as a length and
throws `Invalid NAL length`. Adding `pssh` or going through ClearKey does not change this.

**Resolution**: Dart parses `moov` to build the sample index and IVs, Kotlin provides a decrypting
data source that decrypts per sample before feeding ExoPlayer; the encryption boxes in `moov` are
additionally rewritten in place into **same-size `free` boxes** (`encv` → `avc1` rename), so total
length is unchanged and not a single `stco` offset needs recomputing. **Any byte position can start
from its own counter block, so scrubbing is exact.** That is precisely what beats
"download the whole episode first".

→ [`docs/adr/0005`](docs/adr/0005-client-side-cenc-decryption.md) (measured behavior and pitfalls),
[`docs/adr/0002`](docs/adr/0002-thin-exoplayer-plugin-owns-cenc.md) (the zero-UI Kotlin boundary,
partly superseded by 0005)

### 2. All three stream-resolution tiers, including a third-party mirror

The latter two often return **plaintext streams**, which is exactly the fallback when decryption
breaks — so all three are kept. The cost is that the third-party domain can see which episode you
request; that trade-off **only holds while this APK is never distributed**.

→ [`docs/adr/0004`](docs/adr/0004-all-three-media-resolution-paths.md)

### 3. Two implementations, shared fixtures against silent drift

The protocol was rewritten in Dart (the Go version returns `map[string]any`, which gomobile cannot
export, and a JSON facade or FFI would need an NDK toolchain on Windows), so from that moment there
were two truths. **A wrong signature shows up on-device as "search finds nothing", not as a red
test** — the worst class of bug. Real responses (app JSON, web HTML, mirror API) are stored as
fixtures; Go and Dart each parse them and assert both outputs are equal; signature, SM3, and key
recovery use fixed vectors. Change one line in Go and the Dart test goes red immediately.

→ [`docs/adr/0001`](docs/adr/0001-dart-rewrite-instead-of-gomobile.md),
[`docs/adr/0003`](docs/adr/0003-go-package-as-protocol-truth-with-fixtures.md)

## Known limitations

- **The upstream protocol can change at any time.** If the web `_ROUTER_DATA` structure shifts,
  catalog / search / rankings all break together (fixtures make it a red test).
- **The third-party mirror domain is unstable** and fails outright on key-version upgrades. It is a
  fallback only; losing it does not affect the primary path.
- **About 40% of dramas have no rating at all.** Ratings live only on the web detail page; the app
  API has no such field, so absence is normal, not a failure.
- **Verified item by item on exactly one real device** (Redmi `23013RK75C`, Android 15 / HyperOS);
  no other device was tested.
- **Android only.** No iOS or desktop target exists.
- **No APK is distributed.** See License and ADR-0004.

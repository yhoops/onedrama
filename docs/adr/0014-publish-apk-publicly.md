# 公开发布 APK（推翻 ADR-0004 关于「不外发」的前提）

2026-09-24 起，`yhoops/onedrama` 是**公开**仓库，并在 GitHub Releases 上公开发布
`onedrama-1.3.1-release.apk`。ADR-0004 写的「这条路只在这个 APK 不外发的前提下成立」
与「分发范围因此被限制为私下传包」两条**不再成立**，此 ADR 覆盖它们；0004 关于「三级
取流都搬」的技术决定本身仍然有效。

用户知情后选择公开：已被告知这两条边界与 ADR-0004 的张力，以及下述后果，仍决定公开。

## 接受的是什么

- **第三方备用取流域名**（`djapi.999888456.xyz`）随 APK 一起公开。任何人反编译即可看到
  我们向它请求哪一集——这正是 0004 当初要避免的。
- **红果 App 的请求签名算法与伪装设备参数**（`signRequest`、`appUserAgent` 等）在 APK 里
  可读。0004 说「签名得挪到自建后端」才能公开分发，本次**没有做**这一步。
- **客户端 CENC 解密实现**随包公开。
- 「开源、禁止商用」是 README 里的**自述条款，不是标准许可证**（仓库 `license: None`）。
  它拦不住下载与再分发，只能作为主张；公开分发会让这套逆向实现进入可被检索的范围。

## Considered Options

- **只发源码 Release，不带 APK**：保住 ADR-0004，仓库依旧开源可读。用户选了公开发包。
- **先按 ADR-0004 重做前提**（拿掉第三方域名、签名挪自建后端）再公开：工作量大，且需要
  一个服务端；用户没有选。
- **保持私有仓库**：见 [[onedrama-github-remote-is-private]]——仓库先于本次决定就已经转为公开。

## Consequences

- **几乎不可逆**：Release 附件可被镜像、fork、索引；删除 Release 只能收回我们自己这一份。
  若上游（红果 / 字节）提出异议，能做的只有撤下 Release，仓库本身的历史与索引不随之消失。
- ADR-0004 的「三级取流」代价从「私下传包才可接受」变成「已接受公开」。若将来要收紧，
  可执行的最小动作是：撤下 Release 附件、把第三方域名从代码里去掉、改成只走 App + 网页两级。
- 本 ADR 与 0004 冲突处**以本 ADR 为准**。

# onedrama 模块划分

本文件回答一个问题：**这个项目现在有多少个模块。**

答案取决于「模块」按哪个口径数，四个口径都成立、彼此不可加：

| 口径 | 数量 | 依据 |
| --- | --- | --- |
| **功能模块** | **7** | 路由表（`lib/ui/router.dart`） |
| 构建单元 | 3 | 两份 `pubspec.yaml` + 一份 `go.mod` |
| 代码分层 | 3 | `lib/` 下 `data/` `player/` `ui/` |
| 协议子模块 | Dart 16 / Go 13 | `packages/hongguo_dart/lib/src/` 与 `hongguo/*.go` |

**本项目取功能模块口径：7 个功能模块 + 1 层支撑模块（5 块）。** 理由见文末「口径说明」。

### 1. 短剧库 `/`

首页，也是唯一有多个数据来源的页面：四个一级标签（综合走推荐接口、真人剧 / 漫剧 / AI剧
走分类接口，`LibraryTab.genreKey` 为 null 即综合——标签表在 `lib/data/library_tabs.dart`）、
题材 chip（**跳搜索的快捷词，不是筛选器**
——红果没有题材词表接口）、「上次观看」续播入口（取历史最近一条，点一下直接开播、不绕详情页）、
双列海报流、右上角榜单入口。阶段 5 起改成**本地优先**：有剧库快照就先渲染、**一个请求都不等**，
后台只做「头部有没有新剧」的检查（见 [ADR-0008](adr/0008-library-snapshot-on-every-launch.md)）。

- 文件 `lib/ui/library_page.dart` · 802 行
- 截图 `docs/shots/library-light.jpg`（浅色）

### 2. 榜单 `/rank`

四个榜 Tab + 名次列表 + 下拉刷新 + 分页。**这个模块有两处防御性设计**，都是被站点逼出来的：
上游在两种渲染之间随机摇摆（约一半请求命中的那版 HTML 里压根没有榜单数据），所以每个榜
自动重试几次；全失败时退回上一次成功的结果并写明是哪天的榜单——站点摇摆时给一个错误页，
比给一份旧榜没用得多。

- 文件 `lib/ui/ranking_page.dart` · 560 行
- 截图 `docs/shots/rank-dark.jpg`（深色）

### 3. 搜索 `/search`

边打边出联想；提交后走「网页搜索 ∪ 剧名联想」，按 ID 去重、按标题相关度排序。它有自己的
路由和页面文件，但**入口嵌在短剧库页的搜索框上**，不是底栏一级——这是它容易被误当成
短剧库子功能的地方。

- 文件 `lib/ui/search_page.dart` · 568 行
- 截图 `docs/shots/search-dark.jpg`（深色）

### 4. 详情 `/detail/:seriesId`

竖版沉浸式：模糊封面铺底 + 标题 / 评分 / 热度 / 标签 + 简介可展开 + 选集网格（超 30 集分页）
+ 底部固定「继续观看 / 开始播放」。封面用 Hero 从被点的那张卡上飞过来。评分只可能来自网页
详情——App 接口没有这个字段。

- 文件 `lib/ui/detail_page.dart` · 815 行
- 截图 `docs/shots/detail-dark.jpg`（深色）

### 5. 播放 `/player`

**全项目最大的单文件**（1830 行，占 `lib/` 的 21%）。右竖控制栏（可切左侧）、点屏显隐、
双击播放暂停、左半屏调亮度、右半屏调音量、左右滑拖进度、锁屏、选集 / 收藏 / 倍速 / 画质
面板、自动连播，以及进度落库（暂停与退出各落一次）。

- 文件 `lib/ui/player_page.dart` · 1830 行
- 截图 `docs/shots/player.jpg`

### 6. 我的 `/mine`

收藏 / 历史分段控件 + 空态 + 真实列表（历史带进度条与相对时间）。历史是**从观看进度派生的**
（`CONTEXT.md`：Watch History derived from Watch Progress），所以这个模块只读不写——
「写历史」这件事不存在，播放页写进度，这里读。

- 文件 `lib/ui/mine_page.dart` · 451 行
- 截图 `docs/shots/mine-dark.jpg`（深色）

### 7. 设置 `/settings`

四组设置：主题 / 播放 / 手势与控制 / 剧库与存储。**每一项都真的接线**（不是摆设）：默认倍速
进播放页就应用、优先画质从同一次取流的 `variants` 里挑、自动播放下一集演完就切、记忆播放
进度关掉就不写库、控制栏位置决定竖栏在左还是右。阶段 5 又添了三行，同样接线：**预缓存下一集**
（关掉就完全不预取）、**更新剧库**（手动再跑一轮导入，右侧显示进度或「X 分钟前更新」）、
**清空搜索历史**。

- 文件 `lib/ui/settings_page.dart` · 599 行
- 截图 `docs/shots/settings-light.jpg`（浅色）

**功能模块合计：5625 行，占全项目代码 43%。**

## 二、支撑模块（5）

被上面 7 格共用、没有自己的入口。

### 1. 协议层 · `packages/hongguo_dart` · 3821 行

红果协议的全部实现：签名（`X-Gorgon` / `X-Khronos` / `X-SS-STUB`）、ID 工具、CENC 密钥
还原与**样本解密**、备用接口响应解密、网页解析、分类 / 推荐 / 榜单 / 搜索、三级取流
（App 签名 → 网页 → 第三方备用）。

一个包，两个约束：**不碰 UI、不碰播放器**。协议在 Dart 里重写而不是把 Go 编进 APK
（`docs/adr/0001`），Go 包 `hongguo/` 留在仓库里当协议真相、不进 APK。

### 2. 播放通道 · `lib/player/` 405 行 + Kotlin 494 行 = 899 行

这是全项目**最反直觉**的一块。上游每一路视频都是 AES-128-CTR 加密的，**连 NAL 长度前缀
都加密**，所以没有任何现成提取器能解析——`media3` 的 `Mp4Extractor` 已从源码层面证伪
（`docs/adr/0005`）。改成客户端解密：

```
Dart  cenc_header.dart   取头部 1 MB，解 moov 出样本索引与等长替换补丁
      decrypt_plan.dart  编成一份二进制「解密计划」
      ↓
Kotlin CencDecryptDataSource.kt  在数据源这一层按字节范围二分查样本、就地 AES-CTR 解密
```

关键在于**任意字节位置都能从对应的 counter 块起算**，所以拖动进度条也是对的，
`STATE_READY` 约 2.3 秒落地而不是等整集下完。

### 3. 本地存储与缓存 · 1329 行

sqflite **四张表**：`drama_snapshots` / `favorites` / `watch_progress` / `library_entries`。
**没有 `watch_history` 表**——历史从进度派生，同一件事存两份真相迟早不一致；快照表则是
因为收藏与历史都要显示标题封面，不该为此重拉详情、离线也要能列出来。`library_entries`
是剧库快照（见 [ADR-0008](adr/0008-library-snapshot-on-every-launch.md)），建库版本 2 才有，
加它时只走 `onUpgrade`、不动老数据。

prefs 存设置与 `DeviceID` / `InstallID`，另有搜索历史（`Search History`）与剧库的「上次
更新时间」。缓存这一层现在有四个：剧集（`cenc_<vid>.mp4` **加一份 `.json` 旁挂**，见
[ADR-0009](adr/0009-prefetch-next-episode-as-a-whole-file.md)）、榜单（兜底用）、封面（磁盘 +
内存两层）、以及导入时顺手热的那批封面。

`library_importer.dart` 也算在这一块：它是剧库快照的**唯一写入者**，每次启动跑一遍。

### 4. 网络与装配 · 400 行

dio 拦截器（in-flight 去重 + 详情 / 搜索 / 榜单 5 分钟 TTL；**取流一律不缓存**，因为
`main_url` 带时效签名），以及 Riverpod providers。另加两个阶段 5 才有的小件：
`catalog_pager.dart`（一个标签的分页状态机——首页滚动加载与剧库导入**共用同一套游标
规则**）、`library_tabs.dart`（四个一级标签；**剧库快照按它的下标存**，所以导入器与首页
必须共用这一份，各写一份会错位）。

### 5. 界面公共件 · 1090 行

深浅两套色板（色值取自 `参考的前端页面/` 的红果截图逐像素采样）、go_router 路由表、
底部外壳、海报卡、页面转场、按压缩放反馈、封面预加载、数字格式化、`main.dart`。

**支撑模块合计：7539 行，占全项目代码 57%。**

## 三、口径说明

### 为什么是 7

`lib/ui/router.dart` 里，底栏走 `StatefulShellRoute.indexedStack` 三个分支，另有四条压在
其上的整页路由。**3 + 4 = 7，每条路由恰好对应一个页面文件，没有剩余、没有合并。** 7 不是
主观挑的数字，是路由表数出来的。

### 为什么不是别的数字

- **不是 3**（构建单元）：那是工程组织口径，讲的是依赖方向（Go 不进 APK），不是功能。
- **不是 10**（7 格 + 支撑层平铺）：上下两层性质不同——7 格是「用户能进去的页面」，
  支撑层是「7 格共用的能力」，没有入口。平铺会让人以为有 10 个对等模块。
- **不是 16**（协议子模块）：那是协议层内部的文件划分，比「模块」低一级。

### 为什么一定要带支撑层

只画 7 格会漏掉 **57% 的代码**（7539 行），而且漏掉的恰好是这个项目最有讲头的部分：
客户端 CENC 解密、三级取流降级、Go/Dart 双实现用共享 fixtures 防分叉、每次启动自动重建的
剧库快照。三层框图（功能 7 格 + 支撑 5 块）才和代码量对得上：43% : 57%。

### 已知缺口（诚实记录）

- ~~**设置页没有真机截图**~~：`docs/shots/settings-light.jpg` 于阶段 5 补上，这条已了结。
  （它此前是唯一有页面文件却没有截图的模块。）
- **协议层两侧并不对称**。名义上 Dart 16 个文件对 Go 13 个，但 Go 有 `danmaku.go` 与
  `comment_sign.go` 而 Dart 没有（弹幕与评论签名按 `docs/plan.md` 划在计划外），
  Dart 有 `cenc.dart` / `sm3.dart` 而 Go 没有（Go 那边明确「只给密钥、不解封装」）。
  **真正对称的只有 11 个。**

### 行数口径

只统计手写源码：`lib/` + `packages/hongguo_dart/lib/` + `android/app/src/main/kotlin/`，
合计 13164 行。不含测试、`tool/` 手验脚本、生成的 `GeneratedPluginRegistrant.java`、
`build/` 产物、以及 `参考的前端页面/`（那是设计依据，不是本项目的产物）。
